### 项目关联与标签筛选（提案）

- 每个问答链在结构记录中维护 `relatedProjects` 与 `tagIds`，可关联零个、一个或多个项目。用户明确项目关联可选，空关联是正常完整内容，不要求补全；仍参与问题墙轮换、全部问题展示、标签筛选和问答弹窗阅读。没有关联时隐藏项目区域，不显示「待关联」提示。
- 项目引用使用稳定项目 id，附所属模块以避免跨模块重名（如 `{ module: "projects", id: "crater" }`）；优先接入「项目」，兼容现有共享项目详情组件承载的「课设」。项目名、路由及显示文案从既有项目记录与 i18n 解析，不重复手写标题/URL。
- 问答弹窗的关联项目是可直接导航的链接；点击后关闭弹窗并进入现有项目详情。问题列表中项目链接与「打开问答」触发项独立，避免嵌套按钮/链接和误开弹窗。
- 项目详情增加「相关问题与思考」区：从问答数据按当前项目引用反查，显示问题及作者维护的简短思考摘要，点击打开同一弹窗；无关联时隐藏。视觉模式和朴素模式均接入，不把完整答案重复复制进项目文案。
- 关系只在问答链一侧维护；项目端自动推导，禁止另维护一份 questionIds 清单。一个问答关联多个项目时，可以在各项目中出现，但全问题列表中仍只有一条主题。
- 全部问题页提供可点击标签、多选状态、结果数量及清除筛选。提案采用标签间「或」匹配（任一所选标签即可），未选标签时展示全部；项目范围如启用，则与标签结果取交集，界面明确显示当前范围。
- 项目详情关联条目较多时可用「查看该项目全部问题」跳转带项目范围的 `/questions`，筛选后再分批呈现。筛选与问答选择写入不同 URL 参数，打开/关闭弹窗不丢失当前筛选，刷新/分享可以恢复。
- 标签使用小型统一字典（内部稳定 id + 统一英文名称），所有界面语言下均显示英文标签，避免同义词或大小写将同一标签拆开；每个主题选少量有辨识度的标签，不自动复制关联项目的全部技术栈标签。
- 用户授权结合实际项目内容补全关系；原备注保留，新增关联标注推断，区分项目直接涉及与原理对照，不把后期深入研究倒推为早期项目实践。首批素材已完成关联与英文标签整理。

### 随机叠放与轮换（实现提案）

- 首次进入即有一批问题，不从空白缓慢堆积；完整候选池来自同一公开数据集，按打乱后的循环队列逐步引入新主题，一轮候选耗尽后再洗牌。避免可见区重复显示同一主题。
- 新问题在墙内随机位置出现，层级高于旧问题；旧项经历停留、弱化和移除，形成长期轮换，而非无限增加 DOM 或 z-index。
- 位置采样根据实际容器及条目尺寸约束，允许局部重叠；限制重叠密度，避免新标题被裁切或墙变成不可读的堆叠。随机只在入场/尺寸变化时计算，不在每次 React 渲染时重抽。
- 活跃问题数量随墙面积调整，桌面呈现明显密集感，手机减少同时显示量以保留点击空间；具体数量、间隔、透明度和叠放比例集中配置，在实际内容与用户视觉反馈后调优。
- 提供轻量「暂停/继续」控件。悬停具体问题、键盘焦点进入墙或打开问答弹窗时暂停轮换，保证点击目标稳定；鼠标仅停在墙的空白处不暂停。弹窗关闭恢复原墙面与候选进度。
- 页面隐藏、墙离开视口或组件卸载时停止调度；恢复时继续，不积累隐藏期间的入场任务。有限渲染池与低频调度，不做持续物理模拟或重型 canvas。
- full 可使用克制入场/淡出；默认 static 保留低频问题替换与散落构图，省去连续位移/装饰动效；`prefers-reduced-motion` 默认暂停自动轮换。plain 使用整齐静态问题列表，仍可开同一弹窗。
- 被遮挡的旧项不抢占上层点击；退场/完全不可见项不保留可聚焦按钮。对可见按钮使用可读标题和正常焦点标记，避免频繁播报自动轮换。

### 内容模型（提案）

- `QuestionThread`：稳定 `id`、`tagIds`、`relatedProjects`、可选日期、可选探索状态、规范展示顺序、按作者顺序维护的 `rounds`；可维护主题摘要供项目关联区使用，问题墙从完整公开主题池轮换。
- `QuestionRound`：主题内唯一且稳定的 `id`；本轮问题必填，思考、回答、参考资料可选。一问一答只有一轮，后续轮次沿前文继续追问。
- 主题/轮次 id 不由标题、序号或翻译推导；重排后共享锚点保持稳定。数组顺序体现线性研究脉络，不引入递归树或冗余父子关系。
- 不用「有答案」自动推导「研究已完成」；支持无答案、正在探索和已有阶段性回答。状态如采用，由作者显式维护。
- 结构数据建议放在 `src/data/questions.ts`，主题/轮次文案按稳定 id 放在 `src/content/locales/{zh,en}/questions.json`，英文标签名称集中维护一份；UI 与正文分别维护，问题墙、整齐列表、项目关联区和弹窗读取同一数据源。
- 正文优先使用段落及必要的列表/代码块等结构化内容，按真实首批问题决定富文本最小需求；不默认引入通用 Markdown 编辑器或重型渲染依赖。
- 沿用当前 zh/en；缺失正文译文时回退中文，不能因语言切换丢失轮次。英文实体草稿遵守 SPEC §4.1，应用时告知用户并邀请审阅；本轮未生成英文实体文案。
- 空数据时列表提供明确空态，简历不渲染空整屏；只有少量问题时降低密度，不通过复制相同主题制造大量问题的假象。

### 分深度透视拉远（2026-10-01）

- 参考 [PBRT 投影相机](https://www.pbr-book.org/4ed/Cameras_and_Film/Projective_Camera_Models) 与 [Scratchapixel 投影计算](https://www.scratchapixel.com/lessons/3d-basic-rendering/computing-pixel-coordinates-of-3d-point/mathematics-computing-2d-coordinates-of-3d-points.html)：由 `x=fX/Z` 推导镜头后退后的相对倍率 `s=Z₀/(Z₀+age×retreatPerStep)`；位置为 `center+(initialPosition-center)×s`，框整体也乘 `s`
- 场景构图采用外围偏近、中央偏远：按原始框中心在可放置区域内的归一化径向距离，将初始深度从 1800 插值到 640；这是人为的空间分布，并非屏幕半径天然决定物理深度。深度不随投影后位置重新计算
- 每个框拥有不同的初始深度，所有框每轮经历相同镜头位移；按最新反馈将每轮位移从 80 减半至 40，让深度更浅，近处首轮保留约 94.1%，远处约 97.8%，后续每轮相对收缩逐渐减缓，替代恒定指数缩放
- `QuestionWallLayer` 用 Web Animations API 播放每轮 17 个透视采样关键帧，保持 1000ms 和原缓动；仅轮换时计算，无逐帧 React 更新、无三维依赖、无新增布局测量。浏览器不支持 animate 时直接呈现终态
- 尺寸重排/内容测量更新直接建立新场景；切换 reduced-motion、重排和卸载均取消旧动画，退休节点继续原位淡出，新问题沿用独立落入动画；保留用户要求的新问题优先层级和年龄淡出
- 验证通过：11 项问题测试、相关 ESLint、TypeScript、Vite 生产构建与 diff 空白检查；新增不同深度倍率、等距镜头位移、分数年龄、角点投影一致性与采样中点误差测试。构建仍提示既有大 chunk；按项目约束未开启浏览器预览，实际观感待用户检查
