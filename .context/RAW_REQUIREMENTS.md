# RAW_REQUIREMENTS (Draft)

原始需求，将由 AI 进行分析。

---

这是一个 React 的个人主页，纯前端，主要面向面试官，兼顾社区开源开发者或者同好，主要目的是求职，其次是交友、交流。

使用 GitHub Actions 部署到 **GitHub Pages 用户站**（非项目站）：仓库名为 `AkashiSensei.github.io`，线上地址为 `https://akashisensei.github.io/`。

这个将作为**公开的**个人主页与能力展示延伸，需要比较全面地展示优势与亮点；**不在站点上提供简历等含隐私信息的文件下载**（求职材料通过私下渠道投递）。

页面设计上必须简约清爽，提供深色模式、浅色模式，提供中文、英文、意大利语、日语四种语言；除中文外的站点文案由 AI 翻译生成，发布前需人工校对。设计上保持克制，以内容展示为优先，可以参考 Apple 的液态玻璃风格，但不用真的做出液态玻璃的效果，可以使用毛玻璃的风格，背景稍微添加一些浅的多色渐变。

采用 shadcn/ui：以可复制进项目的组件源码为基础（Radix UI + Tailwind），定制毛玻璃视觉；站点以展示与导航为主，不需要复杂表单与重交互。

必须方便移动端查看和阅读，所有的前端设计必须同步考虑面试官在手机上的查看体验，甚至对移动端的支持要优先于桌面网页。

为了更加全面地展示我，这个网站需要有这些静态的内容模块：
- 项目：课程之外的代码项目。
- 课设：课程设计项目，不仅面向面试官，还面向学弟学妹，提供可以参考的开源仓库。
- 工作台：日常学习与工作中**我使用**的第三方软件、在线服务与工作流平台（非自研，亦非编程语言/框架能力本身）。包括多个类别，比如 AI 辅助工具类（Cursor、Codex、Qclaw、Trae CN），创意软件（Adobe 全家桶），办公软件（Microsoft 365 全家桶、飞书、Acrobat、WPS），三维软件（Blender、C4D），分析软件（Nsight Compute、Nsight Systems、Wireshark），传统开发工具（VS Code、IDEA、Pycharm、Apifox），知识沉淀工具（Evernote、FlowUS、Obsidian、Zotero、MindNow）、虚拟与远程（Docker、Parallel Desktop、Termora、Windows APP）。与 **「方向」** 区分：工作台展示的是长期稳定的工具配置；兴趣与正在探索的领域主题由 **方向** 等数据模块承载，而非工具清单本身。
- 小工具：我为支撑个人其它工作流而**自己编写或作为 Contributor 参与**的开源仓库、脚本或小型程序（含对我自己 fork 的仓库的贡献；条目可优先填写我的 fork 链接）；体量较小，与「项目」区分，通常不作为求职代表作单独主推。
- 知识沉淀：各类文本性质的产物，可能有不同层级，比如外部博客仓库、或者具体文章的链接。我有多个这种性质的仓库，包括技术博客、工程调研、论文阅读等多个仓库。
- 工作经历：实习和工作经历。
- 能力：区别于「工作台」「小工具」等具体条目模块的综合特质与长板（如端到端推进、技术调研与表达、系统思维等）。
- **方向**：我**感兴趣**与**正在投入**的技术/领域主题（可结构化罗列；可与「项目」「知识沉淀」等互链）。区别于「工作台」（长期稳定的第三方工具清单）；兴趣与投入重点以本模块（及首页对应 Highlight）呈现，**不再**依赖首页单独的「当前在做」文案区。
- 信条：个人原则与工作观念，说明如何做取舍与坚持什么。
- 学术成果（暂无）：论文、专利、软著等等。

每个内容模块可能都提供一个页面，来列举和展示该类型下的条目或分组，允许切换展示方式：列表或者画廊。

每个内容模块的条目可能需要关联到其它条目，同类型或跨类型的关联均可。比如一个项目中，可能包含关联的知识沉淀、工作台（所用工具）、小工具、能力与**方向**，需要以标签的形式附着在项目卡片上；桌面端悬停预览（这个可以不着急），移动端可点击展开，点击标签可跳转。也允许一些静态的标签比如“已归档”等等。对于 GitHub 项目，最好能够自动获取 Star 数并展示。

不要直接在页面里面定义每个条目，而是读取数据列表进行展示，方便删改数据，乃至后续改为从后端获取数据。

首页除了简单的自我介绍与**公开的**联系方式外，**每个主要实体类型（内容模块）都应在首页有一块 Highlight 区域**：展示该类型下经策展的若干代表条目（数量可配置，建议每类 1～3 条），并提供进入该模块完整列表页的入口。**学术成果**与**方向**在尚无条目时可不展示 Highlight。更多动态可以跳转 GitHub Profile 页查看。

构建配置须按用户站处理：Vite `base` 固定为 `/`（禁止按项目站配置子路径前缀）。

2026-05-20 需求补充：「工作台」模块需要以可复用的软件组形式展示，并需要配套的 i18n / 内容数据结构支持。

工作台以「软件组」为主要展示实体。每个软件组未来可能包含示意图、标题和多行描述，因此翻译键与实体数据需要单独设计，方便长内容维护，也方便同一份数据在不同页面复用。

工作台软件组需要支持两个展示位置：
- 首页的软件组展示区：初步设计为横向左右滑动查看两三个软件组，最右侧提供「查看全部」跳转卡片。
- 工作台页面的软件组列表：从上到下展示全部软件组。

首页与工作台页面应复用同一个软件组卡片组件；具体视觉、字段与交互细节可后续细化。

2026-05-20 需求补充：「小工具」模块开始落地。

小工具条目需要先通过 GitHub 仓库发现定位：使用 `gh` 访问用户仓库，筛选一些符合“小工具”定位的仓库，与用户确认后再进入内容撰写与页面实现。

确认条目后，阅读对应仓库，为每个条目生成初版中文内容，包含：标题、仓库名、描述和小点列表。用户后续会人工修改这些初稿。

小工具卡片视觉参考工作台软件组卡片，但表达的是用户自己编写或作为 Contributor 参与的小型仓库/脚本/程序。卡片需要支持可选截图：
- 用户可提供截图，也可以暂时不提供。
- 如用户提供多张截图，可按用户要求裁成相同宽高比。
- 卡片顶部展示截图时，图片距离卡片顶部和左右两侧为 0 margin，顶到卡片边缘；圆角卡片本身裁切图片上方两个角。

卡片内容顺序为：顶部截图（可选）、标题、仓库名副标题（带右上箭头表示跳转外部仓库）、描述、小点列表。该模块需要添加到首页 Highlight，并创建新的「小工具」专有页面。
