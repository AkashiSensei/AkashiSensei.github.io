原始需求，将由 AI 进行分析。

这是一个 React 的个人主页，纯前端，主要面向面试官，兼顾社区开源开发者或者同好，主要目的是求职，其次是交友、交流。

使用 GitHub Actions 部署到 **GitHub Pages 用户站**（非项目站）：仓库名为 `AkashiSensei.github.io`，线上地址为 `https://akashisensei.github.io/`。

这个将作为**公开的**个人主页与能力展示延伸，需要比较全面地展示优势与亮点；**不在站点上提供简历等含隐私信息的文件下载**（求职材料通过私下渠道投递）。

页面设计上必须简约清爽，提供深色模式、浅色模式，提供中文、英文、意大利语、日语四种语言；除中文外的站点文案由 AI 翻译生成，发布前需人工校对。设计上保持克制，以内容展示为优先，可以参考 Apple 的液态玻璃风格，但不用真的做出液态玻璃的效果，可以使用毛玻璃的风格，背景稍微添加一些浅的多色渐变。

采用 shadcn/ui：以可复制进项目的组件源码为基础（Radix UI + Tailwind），定制毛玻璃视觉；站点以展示与导航为主，不需要复杂表单与重交互。

必须方便移动端查看和阅读，所有的前端设计必须同步考虑面试官在手机上的查看体验，甚至对移动端的支持要优先于桌面网页。

为了更加全面地展示我，这个网站需要有这些静态的内容模块：
- 项目：课程之外的代码项目。
- 课设：课程设计项目，不仅面向面试官，还面向学弟学妹，提供可以参考的开源仓库。
- 工作台：日常学习与工作中**我使用**的第三方软件、在线服务与工作流平台（非自研，亦非编程语言/框架能力本身）。包括多个类别，比如 AI 辅助工具类（Cursor、Codex、Qclaw、Trae CN），创意软件（Adobe 全家桶），办公软件（Microsoft 365 全家桶、飞书、Acrobat、WPS），三维软件（Blender、C4D），分析软件（Nsight Compute、Nsight Systems、Wireshark），传统开发工具（VS Code、IDEA、Pycharm、Apifox），知识沉淀工具（Evernote、FlowUS、Obsidian、Zotero、MindNow）、虚拟与远程（Docker、Parallel Desktop、Termora、Windows APP）。与 **「方向」** 区分：工作台展示的是长期稳定的工具配置；兴趣与正在探索的领域主题由 **方向** 等数据模块承载，而非工具清单本身。
- 小工具：我为支撑个人其它工作流而**自己编写或作为 Contributor 参与**的开源仓库、脚本或小型程序（含对我自己 fork 的仓库的贡献；条目可优先填写我的 fork 链接）；体量较小，与「项目」区分，通常不作为求职代表作单独主推。
- 知识沉淀：各类文本性质的产物，可能有不同层级，比如外部博客仓库、或者具体文章的链接。我有多个这种性质的仓库，包括技术博客、工程调研、论文阅读等多个仓库。
- 工作经历：实习和工作经历。
- 能力：区别于「工作台」「小工具」等具体条目模块的综合特质与长板（如端到端推进、技术调研与表达、系统思维等）。
- **方向**：我**感兴趣**与**正在投入**的技术/领域主题（可结构化罗列；可与「项目」「知识沉淀」等互链）。区别于「工作台」（长期稳定的第三方工具清单）；兴趣与投入重点以本模块（及首页对应 Highlight）呈现，**不再**依赖首页单独的「当前在做」文案区。
- 信条：个人原则与工作观念，说明如何做取舍与坚持什么。
- 学术成果（暂无）：论文、专利、软著等等。

每个内容模块可能都提供一个页面，来列举和展示该类型下的条目或分组，允许切换展示方式：列表或者画廊。

每个内容模块的条目可能需要关联到其它条目，同类型或跨类型的关联均可。比如一个项目中，可能包含关联的知识沉淀、工作台（所用工具）、小工具、能力与**方向**，需要以标签的形式附着在项目卡片上；桌面端悬停预览（这个可以不着急），移动端可点击展开，点击标签可跳转。也允许一些静态的标签比如“已归档”等等。对于 GitHub 项目，最好能够自动获取 Star 数并展示。

不要直接在页面里面定义每个条目，而是读取数据列表进行展示，方便删改数据，乃至后续改为从后端获取数据。

首页除了简单的自我介绍与**公开的**联系方式外，**每个主要实体类型（内容模块）都应在首页有一块 Highlight 区域**：展示该类型下经策展的若干代表条目（数量可配置，建议每类 1～3 条），并提供进入该模块完整列表页的入口。**学术成果**与**方向**在尚无条目时可不展示 Highlight。更多动态可以跳转 GitHub Profile 页查看。

构建配置须按用户站处理：Vite `base` 固定为 `/`（禁止按项目站配置子路径前缀）。

2026-06-07 需求补充：新设计需要明确适配三类屏幕。

除了移动端与普通桌面端，还需要重点考虑桌面端竖屏或高窄屏幕场景。新的设计至少应先适配三类屏幕：移动端、桌面端竖屏/高窄工作区、桌面端宽屏。之后可以再考虑把现有旧设计也迁移到同一套适配机制。

项目需要建立视觉管理机制，规定和命名各种屏幕尺寸 / 视口档位，并让不同设计变体按这些档位组织布局、导航、阅读宽度、卡片密度和图片展示方式。目标是在任何屏幕上都有较高可读性，保持美观，并具备强设计感，而不是只在宽屏桌面上好看。

2026-06-07 需求补充：视口治理需要放宽宽屏阈值并考虑宽高比。

考虑到现在屏幕分辨率普遍较高，宽屏不应过早从 1200px 开始判定。可以把 1600px 以上视为宽屏；用户主显示器可能显示超过 2400px 宽的浏览器页面，因此超宽场景需要利用空间，但不能让正文被拉得过长。

除了宽度，还需要同时考虑宽高比 / 横竖屏方向。某些设计可以把整个屏幕作为一页内容编排并通过滚动“翻页”，但这种横屏预期的整屏编排在竖屏或高窄屏幕上会显得奇怪；这类场景下应放弃整屏一页，改为自然显示多段内容并向下阅读。

目标是网站在各种屏幕上都有说得过去的显示效果，并在常见情况（手机、普通横屏、普通竖屏 / 高窄工作区）提供优秀效果。

2026-06-08 设计思路记录：2.5D 房间式探索入口。

一个未来可探索的首页 / 展示入口思路：用“我的房间”作为空间隐喻，房间中的家具或物件对应站点内容模块，例如电脑对应项目，桌子或工具区对应工作台，小柜子对应小工具，书架或笔记区对应知识沉淀。用户点击物件后，画面以镜头移动、平移缩放或景深变化的方式靠近对应区域，再展示相关内容。

该设想暂定优先采用 **2.5D 方案**：使用高质量房间插画、分层图片、CSS/Canvas 动画、热点区域和 HTML 内容面板实现，而不是一开始就做完整实时 3D 房间，也不依赖预先准备大量视频。核心内容页面和常规导航仍需保留，房间入口更适合作为探索式体验，而不是替代所有信息架构。

2026-06-08 设计思路记录：滚动航迹（Scrollflight Vista）。

一个未来可探索的电影式首页 / 视觉封面思路：使用一段低帧率或经过优化的视频（例如穿越机飞过用户喜欢的景色）作为背景，但不按时间自动播放，而是让页面滚动进度控制视频时间轴或帧序列。向下滚动时背景前进，向上滚动时背景回退，前景内容则随滚动分章节进入、停留和离开。

实现时优先考虑“滚动进度映射到视频时间轴 / 图片帧序列”，而不是简单地把一次滚轮事件等同于一帧，以避免不同鼠标、触控板和浏览器滚动粒度造成体验不稳定。前景内容应保持克制，可作为根路径首页的 cinematic intro，用少量文字与入口引导到 `/resume`、项目、GitHub 或联系方式；完整简历和长内容仍放在常规页面中。移动端和低性能设备需要静态封面、低帧率或普通纵向内容 fallback。

2026-06-08 设计思路记录：地层索引（Strata Index）。

一个未来可探索的 2.5D 分层滚动首页 / 展示入口思路：描绘一个带有科幻气质的地底锥状避难所、地下研究设施或纵向剖面建筑。页面滚动向下时，视角逐渐深入设施的更底层，并在不同层级展示项目、工作台、小工具、知识沉淀、能力、信条等内容模块。

该方案优先采用 **2.5D 多图层实现**：背景岩层与结构剖面、中景设施/管道/平台、前景遮挡物、灯光、雾气、标识牌和内容热点分层绘制，通过不同滚动速度、透明度和轻微缩放制造纵深。整体方向应偏“冷静工程科幻 / 建筑剖面 / 档案式内容层级”，避免过度赛博、过暗、HUD 噪声过多或游戏化装饰压过内容。移动端可降级为纵向剖面图加自然滚动内容。

2026-06-25 需求补充：项目与课设 bullet 需要从“描述项目本身”转向“说明我做了什么”。

当前很多项目、课设详情中的 bullet 过于执着于介绍系统功能、课程内容或项目背景，削弱了简历最关键的信息：个人在其中承担了什么角色、完成了哪些实现、做出哪些判断、解决了什么问题、产生了怎样的效果。后续需要逐条修订项目与课设文案，保留必要背景，但让 bullet 更像简历经历描述，突出个人贡献、技术动作、取舍与影响。

2026-06-29 需求补充：根路径首页增加“朴素”的显示模式。

当前根路径首页已经有 FPV 视频滚动体验，但还需要提供一个更朴素、低成本、易读的显示模式。朴素模式应保留根首页面向朋友、同好与一般访客的定位，继续提供简短自我介绍、在线简历入口、公开联系方式与 GitHub/Profile 链接，但不应挂载昂贵的视频滚动、Three.js 或 CSS3D 场景。

该模式是首页体验模式，不是重新引入此前暂停的全站样式切换。它需要与现有深浅色、语言切换、导航、联系弹窗、动画/减少动态偏好兼容，并以静态 GitHub Pages 部署为前提。
