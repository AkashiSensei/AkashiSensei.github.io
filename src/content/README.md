# 站点文案（可编辑）

> 本文件只说明内容目录与维护入口。进行开发、内容新增或结构调整前，请先阅读 [项目上下文说明](../../.context/README.md)、[项目规格](../../.context/SPEC.md) 和 [当前任务](../../.context/ACTIVE_TASK.md)；需要追溯原始需求与设计意图时，再查看 [原始需求记录](../../.context/RAW_REQUIREMENTS.md)。项目目标、架构约束、内容与国际化规则、Agent 协作边界及当前任务范围以 `.context/` 中的文档为准。

面向访客的展示文案按语言和领域拆分在：

- `src/content/locales/zh/` — 中文
- `src/content/locales/en/` — 英文

每个语言目录按领域拆分，例如 `common.json`、`nav.json`、`home.json`、`resume.json`、`directions.json`、`workbench.json`、`tools.json`。新增语言时复制同一组文件名，并在 `src/i18n.ts` 注册对应 namespace。

修改后保存即可；开发服务器热更新会重新加载。站点展示名在 `common.json` 的 `site.displayName`（当前为 **Akashi**）；首页标题 `home.title` 通过 i18n 嵌套引用该字段，改一处即可同步到各语言标题。

公开站点**不提供简历下载**；联系方式弹窗属于通用文案，集中在 `common.json` 的 `contactDialog` 中维护。

首页简介 `home.description` 中可使用 `\n\n` 分段；页面使用 `whitespace-pre-line` 渲染换行。简历页文案集中在 `resume.json`，其中 `description` 使用字符串列表，便于逐行修改。

工作台软件组的结构数据在 `src/data/workbench.ts`，标题、说明和要点在各语言的 `workbench.json` 中通过同一个软件组 `id` 对应。

小工具的结构数据在 `src/data/tools.ts`，标题、说明和要点在各语言的 `tools.json` 中通过同一个小工具 `id` 对应。

知识沉淀的结构数据在 `src/data/knowledge.ts`，文案在双语 `knowledge.json` 中。简历卡片最多展示前三条要点，不读取条目级列表上限；完整列表默认三条，需额外展示的条目可设置 `listingPointLimit`，由完整列表卡片、高度估算及朴素索引共用，详情始终展示全部要点。算法刷题记录的完整列表设为四条，末条说明两门课的代码作业。

项目与课设列表的筛选项直接来自 `src/data/projects.ts` / `src/data/course-projects.ts` 的 `tags`，无需维护独立清单；按命中条目数排序，同数保留首次出现顺序。课设年级、学期标签沿用 `course-projects.json` 的 `semesterTags` 翻译，规范值不随语言改变，时间筛选的 URL 使用独立英文标识，例如 `tag=spring-2026`，一项表示整对年级/学期；继续兼容旧中文时间参数。顶部默认全部高亮，首次点击单选、随后可多选（任一标签匹配），取消选择恢复全部。课设将时间筛选放在技术筛选上方，年级与学期从每条数据前两项 tags 成对派生，点击任一标签整对切换；时间组与技术组取交集，组内多选取并集，每组空选择/全选均表示该组不限制。普通/静态模式的时间胶囊沿用既有学期配色，朴素模式保持文档高亮；技术 tag 只高亮实际选中的匹配项。共用控件与样式位于 `TagFilter.tsx` / `tag-filter.css`，筛选及 URL 工具位于 `src/lib/tag-filter.ts`，课设分组与绑定逻辑位于 `CourseProjectTagFilter.tsx` / `src/lib/course-project-filter.ts`，通用文案位于 `common.json` 的 `tagFilter`；问题列表也复用控件与选择逻辑。移动端（768px 以下）项目与课设筛选默认收起，通过双语按钮展开；折叠保留筛选条件，移动端取消选择放在展开/收起按钮右侧，桌面直接展示筛选且取消选择保留在标题区。展开状态不随语言、主题、展示模式或窗口尺寸变化而重置。运行 `npm run test:tags` 验证两套数据的筛选与翻译。

新增或替换图片时，先将运行时引用的素材转为 WebP（确实不适合 WebP 的动图等例外除外）。添加到 `src/data/projects.ts`、`src/data/course-projects.ts`、`src/data/tools.ts` 或 `src/data/knowledge.ts` 后，还需要检查图片是否过白、过亮；如果是白底面积很大或深色模式下会刺眼的截图，在对应图片对象上添加 `brightness: "high"`，让深色模式自动叠加统一的暗色半透明遮罩。

加载逻辑在 `src/i18n.ts`。

项目和课设的所有 bullet 统一使用 `**总结**：具体说明`（英文 `**Summary**: Explanation`）。仅总结部分加粗，冒号与说明使用正文字重，复用现有强调渲染；个人贡献总结体现工程、分析或协作能力，再以具体动作与证据支撑，项目背景总结保持平台功能和团队成果的事实归属。中英文同步维护，保留既有 `projectIntro` / `personalWork` 分节及数组结构，详情允许比简历保留更多过程和技术细节。

问题墙的结构数据集中在 `src/data/questions.json`：每个主题有稳定内部标识、有序轮次、英文标签引用和可为空的项目关联。问题与回答正文在 `src/content/locales/zh/questions.json` 和 `src/content/locales/en/questions.json` 的 `items` 中按同一主题和轮次对应，两者同时提供界面文案。中文保留原始疑问与追问，英文采用简洁自然的表达，保留技术含义、推理顺序与不确定性；新增或修改问答时同步维护两种语言。英文正文未录入时回退到对应中文轮次；整条问答缺少英文时，阅读层的辅助说明会提示中文来源。支持正文中的反引号代码、双星号强调及换行，不执行原始 HTML。

新增问答链追加到 `threads` 末尾，以录入顺序作为新旧顺序；独立问题页倒序展示，标签筛选后仍保持从新到旧，桌面双栏按问题气泡与标签的实际高度进行瀑布流排列，按新到旧依次接到较短的一栏，保持新问题优先出现在上方；窄屏按原顺序单栏显示。修改既有问答不改变其顺序。折叠条目的首问右上角通过共享 `QuestionRoundCount` 显示小圆圈，数字直接取 `rounds.length`，大于 1 才展示，单轮隐藏；问题列表、简历墙与项目相关问题共用规则，朴素入口也保留标记，阅读层不重复显示。数字使用共享字号、主题色和边框，数字圈为 2rem，压在气泡右上圆角，中心距右沿和上沿均 .5rem，复用标签的轻微外阴影；有标记气泡的右侧内边距为 2rem，双标记入口最小高度为 3.75rem，长正文仍自然撑开，动态墙的隐藏测量样本与可见气泡保持一致；`pairCount` 提供双语无障碍说明。共享 `QuestionImageIndicator` 在右下角以圆圈图片图标提示整条链有图，通过 `questionThreadHasImages` 检查全部轮次的问题和回答配图；无图隐藏，单轮有图也显示。图片圈为 2.25rem（36px），略大于数字圈，压在右下圆角，中心距右沿和下沿均 .625rem，略向左上内收；图标放大至 20px，与计数共用表面、边框和阴影，形成消息回应叠在气泡上的效果。朴素文本入口右侧留白为 2.5rem；标签与气泡间留足外沿空间；动态墙四周预留 1.25rem 并同步扣除可布局宽高，避免圆圈被裁切，`hasImages` 提供双语无障碍说明。简历动态墙随机展示并轮换，简洁模式每次挂载随机抽取最多 8 条，浏览期间保持稳定。

问答阅读层通过 `QuestionConversationPresence` 在卸载前捕获退出画面，立即卸载 Radix 弹窗以释放滚动锁和输入拦截；`question-conversation-animation.ts` 仅短暂保留 inert、aria-hidden、禁止指针事件且移除 ID 的 DOM 副本，保存阅读滚动位置、尺寸及当前动画状态。入场沿用 500ms / 70ms 错峰，退出采用 200ms / 35ms，仅为当前可见条目依次分配延迟，文字和图片使用同一上移距离，保留逐条上推效果并避免大图追上前面的文字；退出完成或超时清理副本，重新打开时移除旧副本，reduced-motion 直接关闭。背景页滚轮、触摸板与触摸滚动无需等待动画结束。

主题、轮次的内部标识用于分享链接，编辑标题或调整顺序时应保持不变；作者维护的素材表不需要 ID 列。`tagIds` 对应结构文件中统一英文标签字典。`relatedProjects` 可以为空；有值时使用 `module`（`projects` 或 `course-projects`）与既有项目 `id`，项目详情的「相关问题与思考」自动反查，不维护第二份关联清单。关系的 `note` 保留素材中的推断或对照说明，显示在项目链接提示中。

问题可在结构数据中配置 `questionImages` 与 `answerImages`，均以轮次 ID 为键，值为图片引用数组。项目图片继续使用 `"opening": [{ "module": "course-projects", "id": "parallel-programming-2026", "imageKey": "ncuSharedMemory8192" }]`，通过项目 `images` 中对应的 `altKey` 解析，复用原图路径、尺寸、多语言替代文本和亮度标记。独立问答配图直接配置 `{ "src": "/assets/questions/example.webp", "altKey": "items.thread-id.images.example", "width": 3200, "height": 2050, "brightness": "high" }`，图片存于 `public/assets/questions/`，替代文本在双语 `questions.json` 的对应条目 `images` 中维护，不借用项目图库或自动增加项目关联。问题配图显示在问题与回答之间的左侧气泡，回答补图显示在回答下方的右侧气泡；均保留自然比例、预留尺寸、亮度遮罩及独立错峰进出，并通过共享 `ProjectImageGallery` 点击或键盘放大。简历墙和问题索引只展示首问文本及折叠标记，不直接展示配图。独立配图若有英文版本，可在同一引用配置 `localizedSources.en: { src, width, height }`，默认 `src` 与尺寸用于中文；`localizeQuestionImage` 依据当前界面语言选择资源和对应尺寸，气泡及共享放大图使用同一结果，无对应版本时保留默认图。同一图跨链复用相同路径，不复制多份文件；图片中的版本范围在双语替代文本中说明。

简历简介之后先展示教育经历，再展示项目；普通/静态模式接着展示兴趣、活跃度与课设；课设之后依次展示问题墙、博客精选、工作台、知识沉淀、小工具，普通与朴素模式顺序一致；`/questions` 支持标签、项目范围和分批阅读。各入口共用问答弹窗，`question` 与 `round` 查询参数可以定位具体问答。执行 `npm run test:questions` 可检查数据引用、筛选及轮换边界。


博客原文继续在 `blog-article` 编写；站点发布清单为 `src/content/blog/publish.json`，按稳定文章 ID 指定双语文件、摘要、分类、标签、审阅状态和项目关联，不自动扫描或发布其他草稿。当前显式收录 9 篇双语文章，包括初始收录的 7 篇，以及用户指定的 `cloud-and-ai-infra/crater-job-admission-control`（《基于 Volcano 的 AI 作业接纳与调度》）和 `cloud-and-ai-infra/ceph-mon-election-crash`（《一份异常 FSMap，如何让 Ceph MON 反复崩溃》），覆盖 AI 提效、云计算与 AI 基础设施、工程实践三类；封面单独声明，简介为站点维护的双语摘要。运行 `npm run import:blog -- /path/to/content-repository`（或设置 `BLOG_SOURCE_DIR`）生成 `src/content/blog/generated.json` 及 `public/assets/blog/` 中的 WebP 位图及 SVG 矢量配图；生成文件由脚本维护，修改原稿后重新导入，不能在站点快照里手动改正文。当前快照随站点版本保存，构建时检查发布清单与图片完整性，不在访客浏览器中读取 GitHub；远端内容自动取得流程尚未接入。

简历博客精选通过 `src/data/blog.ts` 的稳定 ID 顺序引用现有文章实体，当前为《基于 Volcano 的 AI 作业接纳与调度》（`crater-job-admission-control`）、CLI 工具设计、RDMA 内存锁定上限。`BlogHighlights` 位于问题墙与工作台之间，复用 `BlogCard` 与 `ArchiveSectionHeader`：普通/静态宽屏三列、手机单列且显示全部三篇，朴素模式沿用知识精选的两列/手机单列。各卡片顶端对齐，按实际内容决定高度，不做等高拉伸。卡片内容、语言、图片轮播/预览和链接均由博客现有管线维护；精选不裁掉简介，模块高度可随内容增长。

作者的后续补充单独维护在 `src/content/blog/author-notes.json`，不写进导入快照，也不修改源文章 Markdown。每条使用稳定的 `id`、所属 `articleId`，可选 `publishedAt` 使用完整的 `YYYY-MM-DD` 日期，未知时省略，不仅存月日展示文本；`locales.zh/en` 分别保存 `markdown` 内容和 `anchor`。`anchor.kind: "section-end"` 使用原文标题的纯文本定位，插在该节（含下级小节）末尾；`"after-paragraph"` 使用完整顶层段落的纯文本定位，插在该段后。标题/段落的内联格式不计入匹配文本。两种锚点均要求唯一匹配，缺失或重复时保留在正文末尾；运行 `npm run test:blog` 可检查现有补充的中英文锚点是否仍然有效。未提供某语言补充时不混入另一种语言。当前 CLI keyring 补充按用户提到的年份保存为 `2026-09-28`；显示时以访客当前年份判断，同年显示 `09-28`，非同年显示完整 `2026-09-28`，无需跨年重新导入或构建。作者名使用站点展示名。作者补充不进入目录，也不改变原文章字数、阅读时间和章节链接。

作者补充在普通/静态模式使用共享实色主题框：`site-accent-surface` 为浅色浅蓝、深色深蓝，边框用 `site-accent-border`，不使用 GlassPanel 的毛玻璃效果；朴素模式保留简洁的主题色左边线。目录浮层与入口是独立角色，继续保留其毛玻璃样式。

QClaw 的后续评论 `qclaw-shutdown-update` 位于第一部分“缘起 / Why I tried it”末尾、第二部分“使用体验 / User experience”之前，复用同一双语补充管线。用户确认评论刚发布，日期保存为 `2026-10-08`；正文中的公告日期和计划停运日期不作为评论日期。

AI PR Review 的后续评论 `ai-pr-review-design-limits-update` 位于引言“先说关键结论 / Here is the key conclusion first”段落之后、瑞士奶酪模型介绍之前，使用双语 `after-paragraph` 锚点。补充日期为 `2026-10-12`，讨论静态审查对业务逻辑与设计的局限，以及让 AI 解释设计和逻辑、由人类进一步判断的做法；日期属于作者补充，不修改文章首次发布日期。

CLI 设计文章的三条完成情况补充分别为 `cli-distribution-completed-update`、`cli-release-versioning-completed-update`、`cli-api-compatibility-completed-update`，通过双语 `section-end` 锚点插在分发、更新与版本管理、API 版本管理三个 ToDo 小节末尾。补充日期为 `2026-10-17`，中文保留作者提供的原话；原 ToDo 标题、正文、阅读统计与文章发布日期保持不变。

博客列表副标题下的“也在知乎”（Also on Zhihu）入口，用简短文案说明同样的文章也发布在知乎；按钮使用联系方式中的填充社交胶囊和知乎图标，共用 `socialPillActionClassName`；手机/桌面的尺寸、主题色、悬浮与焦点反馈由同一入口维护。朴素模式保留文档外链样式。

标题默认从源 Markdown 提取；站点需要调整展示文案时，可在发布清单的 `locales.zh/en.title` 中设置可选覆盖，不改源稿。导入时仍先剥离源标题，再应用展示标题，列表、详情与相关文章读取同一结果；快照校验检查覆盖是否一致。当前 Codex 手机远控文章的双语标题去掉“（已解决）” / “Solved:”，封面替代文字同步。

简介维护在发布清单的 `locales.zh.summary` / `locales.en.summary`，不是自动截取正文；列表卡片和阅读页导语共用这一份内容。用一个连贯段落说明背景或动机、文章展开顺序以及核心内容，中英文范围保持对应；根据正文区分已验证结果、个人体验、推测与待完善事项。修改简介后同样重新导入，不直接改生成快照。

博客卡片与阅读页共用 `BlogArticleMetadata` 元信息组件：默认 card 变体放在卡片标题上方，左侧为字数/词数与预计阅读时间，右侧为 `publishedAt`。reader 变体放在 tag 之后，按发布时间、字数/词数、预计阅读时间依次排列，用 `·` 分隔并全部左对齐，字号稍大。两种布局在窄屏均可换行，卡片日期继续靠右，阅读页信息继续靠左。导入器按语言生成 `readingStats`，不手工维护数字：统计正文中的可读文字与行内代码，排除页标题/简介、Markdown 标记、链接目标、图片说明、代码块和公式源码；中文按汉字及非汉字单词计数，英文按单词计数。阅读时间按中文约 300 字/分钟、英文约 200 词/分钟向上取整，仅作估计；实际显示语言回退时也沿用实际正文的统计。快照检查重新计算统计以发现过期数据。

阅读页关联项目位于完整正文末尾，与上方段落、图片或作者补充保留清晰的纵向间距，复用问题墙的共享 `ProjectSummary`（计数头部、项目图标、类型/名称和右箭头链接行）；朴素博客使用无框展示和共享文档下划线。标题区在发布时间/阅读元信息下方另以共享 `ProjectLinks` 的 text 变体展示项目链接，一行一个，包含类型、名称和右箭头，不加框或计数头部。两处关系均取发布清单的 `relatedProjects`，没有关联时不占位；问题阅读框继续使用同一组件与原有留白/会话动画。

封面与正文独立：在发布清单的每个语言配置中设置可选 `cover: { "file": "images/0-volcano-cover.png", "alt": "封面描述" }`，文件路径相对于该文章的 `directory`，可按语言使用不同封面和描述；没有封面时省略字段。导入脚本将封面单独转换 WebP、记录尺寸/亮度/校验和，并将源封面计入内容指纹，不要求 Markdown 引用封面，也不把正文首图自动当作封面。阅读页在标题介绍区之后、Markdown 正文之前显示独立封面，沿用正文图片的自然比例与亮度遮罩，不加卡片或重复图注；封面和正文图片同用封面优先、去重后的共享大图序列，没有封面时直接展示正文。源内容仓库的元数据规范正在整理，当前显式映射是网站侧的临时入口。

博客列表在普通/静态模式复用项目卡片，朴素模式无框；头图轮播依次展示独立封面与当前语言正文中所有配图，按源路径去重，点击打开共享大图查看器。列表采用按实际内容高度平衡的两列布局（768px 起），手机按规范文章顺序单列展示；新增文章无需维护另一份轮播图片清单。

朴素模式博客条目之间保留更宽的纵向留白，条目内部图片与文字、文字块之间的间距稍紧，让上一篇描述与下一篇头图有清晰间隔，也便于辨认每篇的内容分组；由列表 li 的底部 padding 参与现有瀑布流高度测量，横向列距与普通/静态模式不受影响。

博客专栏在卡片及阅读页的标签行首位展示，普通/静态模式复用共享彩色胶囊（AI 提效紫色、云计算天蓝色、工程实践绿色），按 category ID 固定颜色；朴素模式复用无框 DocumentTag，不加选中高亮。博客卡片不再单列中英文阅读按钮；标题链接覆盖卡片文字、标签和留白区域，进入时携带当前站点语言。图片区域继续单独放大，不触发文章导航；读者通过站点顶部统一语言控件切换语言，文章链接的 lang 查询参数同步更新；阅读页外链行只保留“知乎发布页”，不再列出独立语言按钮或原文仓库入口。

文章使用标准 Markdown / GFM：行内公式写作 `$E=mc^2$`，独立公式使用单独行的 `$$` 围住 LaTeX；公式由 KaTeX 渲染并保留辅助阅读用的 MathML。代码块用三反引号并填写语言名，表格中可用 `<br>` 换行；其他原始 HTML 不执行。脚本提取首行文章标题，阅读层统一正文标题层级并生成目录，不改写源稿。英文文章的 `reviewed` 仅在人工审阅后改为 `true`。位图自动转换 WebP；对于本地 PNG/JPEG/WebP 引用，导入器优先使用同目录、同主文件名的 `.svg`，直接引用 SVG 时同样保留矢量原文件，不做运行时栅格化。SVG 沿用尺寸、亮度检测、校验和、内容指纹与共享图片查看流程，后续重新导入不会退回位图；含中文或空格的源文件名生成稳定 ASCII 文件名，避免 Markdown/browser URL 编码与图片元数据键不一致，原始文件名保留在源仓库。亮度较高的图沿用站点深色模式遮罩。博客新增界面文案在双语 `blog.json` 中维护。

正文中独立占满单行的 `**加粗文本**`（含相邻正文仅以换行分隔的情况）按正文三级标题展示，与 `### 标题` 共用样式、目录与定位复制。页面主标题之外，正文 `#` / `##` / `###` 分别渲染为 h2 / h3 / h4。列表、表格、引用、代码以及普通行内加粗不自动变成标题；新增加粗标题的锚点使用 `section-bold-N`，不改变既有显式标题的 `section-N` 链接。

目录统一由 `BlogTableOfContents` 渲染并读取同一阅读位置。宽屏横屏使用侧栏；其他布局通过 `BlogFloatingToc` 在右下角展开，手机入口位于底部菜单栏上方，不再在文章开头放折叠目录。浮层仅展示紧凑的章节链接，不含可见“目录”标题和关闭按钮，保留无障碍名称；宽度按标题和缩进自适应，在视口范围内限制最大宽度，长标题换行，面板保留较宽 padding。普通项为轻字重与二级对比度，当前项使用稍大的正文角色字号、一级对比度与中等字重，并保留渐变与 reduced-motion。展开后当前章节自动保持可见，点击锚点跳转并收起；浮层使用共享按钮/玻璃表面，支持面板内滚动、点击外部/Escape 关闭与焦点回到入口，朴素模式保留链接下划线。 阅读位置由桌面与移动共享计算：所有标题按顶部定位线切换；封面及无标题引言阶段不高亮，向上滚回首标题的定位线之前也取消高亮。没有标题时不显示当前位置。
